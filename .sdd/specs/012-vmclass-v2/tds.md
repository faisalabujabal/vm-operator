# Test Design Specification: Flex VM Classes

- **Status**: Draft; design only, no claim of implemented or passing tests.
- **Epic**: vmop-4034; implementation ownership follows [tasks.md](tasks.md).
- **Contract**: [spec.md](spec.md), [model.md](model.md), [plan.md](plan.md).
- **Execution plan**: [test-plan.md](test-plan.md).
- **Pattern**: numbered observable scenarios and separate execution plan, as in [spec 009](../009-virtualmachinereplicaset/tds.md).

## 1. Scope and test tiers

Milestone 1 covers provider classes, conversion, admission, compatibility, governance, placement, reserved profiles, upgrade and the shared capability. Milestone 2 coverage is separate and must not block Milestone 1 enablement. The spec remains authoritative; unresolved decisions below are not new product requirements.

**I** means integration through a real envtest API server with generated CRDs, CEL, conversion and admission webhooks installed, and the relevant manager/controllers running. Use a fake provider only for controlled backend responses. **V** adds vcsim at the provider boundary to inspect configuration and power operations. **E** means a real Supervisor/vCenter testbed. Unit tables complement these tiers for exhaustive value/matcher combinations; they do not prove admission registration, storage conversion or controller watches. Envtest has no normal Kubernetes garbage collector or authorization controller setup by default; it does not prove production RBAC or provider namespace copying. Vcsim does not prove GPU support, reserved capacity allocation or real placement.

Every row below specifies an independently reportable scenario family. Parameterize each stated variant and identify the row in test names/results. An E designation requires the stated user-facing workflow on hardware; it does not imply repeating every schema boundary permutation there.

## 7. Cross-cutting assertions and unresolved decisions

Use Eventually/Consistently with fresh API/backend reads and bounded timeouts, never sleeps. An admission rejection must leave stored state unchanged; match the error category and relevant field/reason rather than the complete sentence. For successful controller cases, check observedGeneration and Ready where defined, plus the scenario-specific conditions and actual backend state. Repeat reconciliation to prove convergence without spec drift, duplicate zone entries or redundant backend writes. Do not treat a condition as the sole proof that a power/configuration operation occurred.

Existing open decisions remain visible: T010 association-zone rejection ownership (F04/F32); T011 hardware-version schema and upgrade semantics (F01/F21); T012 unreserved-DirectPath compatibility reason (F22/F25); T014 RP3/RP8 (reserved-profile discovery); T018 live profile/slot semantics (F30/F31); T019 general enum empty values (F02); and M2 branch existingVMs/CPU feature-mask policy (F35/F36). Mark only the affected variants blocked, with the task and required decision. Missing provider publication, multi-zone GPU hardware or an upgrade source is a prerequisite gap, never a passing test. This document does not resolve these questions by copying current implementation behavior.
